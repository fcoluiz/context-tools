# Busca de símbolo (symbols + outline) — mapa de área

Os dois scripts que respondem "onde X está?". Andam juntos por import: `symbols.mjs` consome `symbolsForCode` de `outline.mjs` — mexer no parser afeta os dois. Os scripts são compartilhados entre Claude e Codex; a diferença de host fica nos adaptadores, na configuração e no estado, não no índice. Os outros scripts do plugin (`coupling.mjs`, `audit-docs.mjs`) são concerns separados, não cobertos aqui.

## Por onde começar (símbolo → arquivo)
- `parserForExt(ext)` → `outline.mjs` — **fonte única do despacho por extensão**; `symbols.mjs` importa daqui, então adicionar linguagem nova não exige mexer nos dois arquivos. Devolve `null` quando não reconhece (o chamador diz que não reconheceu, em vez de devolver vazio).
- `symbolsForCode(lines)` → `outline.mjs` — parser JS/TS. Regex linha-a-linha, sem AST.
- `symbolsForPascal(lines)` → `outline.mjs` — parser Delphi/Pascal (`.pas`, `.dpr`, `.dpk`, `.inc`).
- `symbolsForRust(lines)` → `outline.mjs` — parser Rust (`.rs`).
- `symbolsForPython(lines)` → `outline.mjs` — parser Python (`.py`, `.pyi`); `semTextoPython` tira docstring antes.
- `symbolsForGo(lines)` → `outline.mjs` — parser Go (`.go`); `semTextoGo` tira `/* */` e raw string.
- `symbolsForDfm(lines)` → `outline.mjs` — hierarquia de componentes de formulário (`.dfm`, `.fmx`).
- `symbolsForMarkdown(lines)` → `outline.mjs` — variante pra `.md` (headings viram seções).
- Métricas sem conteúdo → `symbols.mjs` grava a classificação agregada de consultas (símbolo, arquivo, sem resultado) e `language-demand` registra só a extensão quando uma consulta por arquivo não suportada falha ou `outline.mjs` recebe um arquivo sem parser. `health.mjs` usa esses sinais para orientar análise de utilidade e demanda futura; não salvam termos/caminhos pesquisados e não ampliam o parser automaticamente.
- `bareName(kind)` → `symbols.mjs` — converte o rótulo em nome pesquisável, cobrindo JS/TS, Pascal e Rust.
- `buildIndex(root, cfg)` → `symbols.mjs` — varre, lê e indexa tudo; devolve `{defs, byFile, byFilePos, fileCount, files, repos, snapshot}`. `repos` é a lista de nomes dos repos realmente varridos (ver `escopoLabel`, abaixo); `byFilePos` é `arquivo → [{name}]` de TODO símbolo daquele arquivo, na ordem em que o parser achou — alimenta `irmaosPorPrefixo`. `files` é a lista de caminhos relativos realmente indexados. `snapshot` (`lib/snapshot.mjs`, `loadSnapshot`/`saveSnapshot`) é metadado de descoberta (parser/tier/fileCount/lista de arquivos/contagem de símbolos) persistido em `.context-tools-snapshot.json` — camada para outros scripts (ex. `context-pack.mjs`) saberem se o índice mudou sem reconstruir; não é segunda fonte de verdade, o cache de símbolos continua validando por `mtime`+`size`+assinatura do parser por conta própria.
- `reportOne(query, index, opts)` → `symbols.mjs` — uma consulta contra o índice já pronto; só monta linhas, não imprime (é o que torna o modo lote possível). Toda resposta (acerto, arquivo, ou nenhum) leva o escopo varrido.
- `escopoLabel(repos)` → `symbols.mjs` — formata `index.repos` para ir em toda resposta; trunca com `+N` acima de 3 repos.
- `irmaosPorPrefixo(nomeAlvo, arquivo, byFilePos)` → `symbols.mjs` — "que outros símbolos do MESMO arquivo têm nome parecido com este?", por maior prefixo em comum (`lcp`), limiar `LCP_MINIMO_IRMAO = 6`, corte em `MAX_IRMAOS_MOSTRADOS = 5` (o resto vira contador `+N`). Chamado por `formatarAcertos` para cada acerto mostrado.

## Invariantes (não dá pra inferir de um arquivo só)
- **Dois tiers, escolhidos automaticamente pela contagem de arquivos** (`CACHE_TIER_MIN_FILES = 300`, exportado para o teste importar em vez de copiar). Tier A (abaixo): reconstrói tudo, nada cacheado ⇒ nada defasa. Tier B (acima): cache com invalidação por `mtime`+`size`. **O limiar NÃO é ponto de equilíbrio de desempenho** — medido em 2026-08-04, o cache vence em TODO tamanho: cobra 36 arq 92→19 ms · flask 83 145→26 ms · 679 963→77 ms · 974 1.794→142 ms · 1.543 1.752→130 ms. Não há cruzamento, logo o limiar é botão de RISCO: abaixo dele o rebuild compra a certeza de que nada defasa. Régua dos 300 = ganho absoluto (~100 ms abaixo não paga; 0,9-1,7 s acima paga). O valor antigo era 2.000, escolhido supondo que o custo abaixo fosse "milissegundos" — eram 1,75 s no workspace real. Em escala grande a degradação é superlinear: 5.000 → 1.859 ms · 20.000 → **17.809 ms** (com cache, ~1,2 s).
- **O tier aparece na saída** (`tierLabel`) — numa ferramenta distribuída o usuário precisa saber se está lendo disco ou cache para poder desconfiar.
- **Invalidação do cache tem 4 gatilhos, todos testados:** arquivo alterado (mtime+size), arquivo novo/removido, **parser alterado** (assinatura derivada do mtime+size do próprio `outline.mjs` — automático, não depende de alguém subir um número à mão), e `root` diferente (cache copiado entre projetos é descartado). Cache corrompido → rebuild, nunca erro. `--fresh` é escotilha manual.
- **O cache só é reescrito se algo mudou** — evita regravar um JSON grande a cada consulta.
- **O custo é construir o índice, não consultar** (consulta é <1 ms). Por isso `symbols.mjs` aceita **vários nomes numa chamada** e constrói o índice uma vez só — 3 símbolos em 3 chamadas custavam ~1,4 s; em lote, ~0,5 s.
- **Prioridade de resposta: símbolo > arquivo > desistir.** Sem definição de símbolo, tenta casar **nome de arquivo** (`byFile`, basename sem extensão) antes de mandar pro Grep. Motivo medido: de 10 buscas reais, 2 falhavam e ambas eram nome de módulo (`paymentService` existe como arquivo, não como símbolo) — cada falha custava um round-trip inteiro.
- **Arquivo NUNCA é apresentado como definição.** O bloco de fallback rotula explicitamente "0 definições, mas N ARQUIVO(S)" e sugere `outline.mjs`. 92,9% dos basenames deste workspace são únicos, mas confundir os dois mandaria o Read pra linha errada — que é o erro que a ferramenta inteira existe pra evitar.
- **Falha visível, sempre.** Nenhum caminho devolve vazio: sem símbolo e sem arquivo, o script diz o que não achou, explica o que o índice não enxerga (variável local, chave de config, coluna de banco) e manda pro `rg`.
- **"0 arquivos indexáveis" tem DUAS causas, e o remédio de uma não serve para a outra** (`extensoesNaoSuportadas`, só roda no caminho de falha). Pasta errada ⇒ ajustar `--root`/`sourceDirs` resolve. Projeto inteiro numa linguagem que o índice não lê (Rust, Python, Go) ⇒ **nenhum ajuste resolve**, e o script agora diz isso explicitamente, com as extensões que achou e quantas. Medido num repo Rust real: antes a mensagem mandava mexer na config, e seguir o conselho devolvia a mensagem idêntica — falha visível não basta se o diagnóstico manda o usuário para um beco sem saída.
- **Padrão de regex inválido não derruba as outras consultas do lote** — `reportOne` captura por consulta.
- **Acerto mostrado inclui "irmãos por prefixo" do MESMO arquivo — string pura, sem conhecimento de linguagem ou convenção.** Motivado por caso real (2026-08-05): um símbolo Pascal (`TExporter.RegistroABC`) tinha irmãos óbvios (`RegistroXYZ`, `RegistroLMNO`) que só apareceram numa busca de subagente de exploração ampla, bem mais cara — a busca pontual parou no primeiro acerto e não generalizou pra família. O limiar (`LCP_MINIMO_IRMAO = 6`) foi MEDIDO, não chutado: em dois codebases reais e bem diferentes (Node/JS deste plugin, React/TS de um projeto à parte), prefixo ≥4 ou ≥5 caracteres pegava até 62% dos símbolos com médias de 9-23 "irmãos" por acerto — ruído, não sinal; ≥6 estabiliza em grupos pequenos e coerentes (`analyze`↔`analyzeSessions`, `Accordion`↔`AccordionItem`/`AccordionTrigger`/`AccordionContent`). Corta em 5 (`MAX_IRMAOS_MOSTRADOS`) com o resto contado, porque o pool pode ser grande (React chegou a 24 num arquivo só) mesmo com o limiar alto — a ordenação por prefixo mais longo primeiro garante que o corte nunca esconde o candidato mais forte.
- **Toda resposta nomeia o escopo realmente varrido (`repos` em `buildIndex`, formatado por `escopoLabel`), inclusive quando NÃO acha nada.** `findRepos` nunca sobe de `root` para pasta irmã POR CONTA PRÓPRIA (mesma fronteira que a correção de `sourceDirs: "../vizinho"` fixou como intencional). Caso real (2026-08-05): um projeto Delphi tinha uma dependência (`uExporter.pas`) num repo IRMÃO referenciado só por caminho relativo num `.dpr`, fora da raiz indexada. O `PreToolUse` respondeu com uma função de OUTRO módulo do mesmo repo, sem nenhum sinal de que o repo certo nem foi olhado — quem lê não tinha como distinguir "achei a resposta certa" de "achei algo, mas fora do lugar". Nomear o escopo (`— scope: NomeDoRepo`) não amplia o índice sozinho (ampliar automaticamente reabriria a mesma classe de vulnerabilidade que a correção de `sourceDirs` fechou) — só torna a fronteira visível para quem lê. A ampliação EXPLÍCITA existe (ver `extraRepos`, abaixo), mas é sempre opt-in, nunca automática.
- **`extraRepos` (`.claude/context-tools.json`) declara repo irmão explicitamente, para quando nem o workspace-misto nem reabrir a sessão na pasta pai resolvem.** Caso real (2026-08-05, mesma investigação do bullet acima): o usuário confirmou que `AppConnection`/`AppDesktop`/`shared` não têm `.git` próprio, então em teoria o fix de workspace-misto (`findRepos`, ver `context-maps-hook`) resolveria — MAS só se a raiz da sessão fosse a pasta PAI de todos. Não é viável: a pasta pai tem dezenas de outros projetos que o usuário não quer no índice, e a raiz PRECISA continuar sendo `AppServer` especificamente. `resolveExtraRepos(root, cfg)` (`lib/roots.mjs`) resolve `cfg.extraRepos` (lista de caminhos relativos à raiz) e só aceita o que fica dentro da subárvore da pasta PAI da raiz — sai daí (`../../mais-fundo`) é recusado, silenciosamente ignorado com aviso em stderr. `findRepos` funde essas entradas com o resto do laço, deduplicando por caminho resolvido; cada consumidor de `requireGit:false` (`symbols`, `coupling`, `audit-docs`, `context-maps`) passa seu `cfg`/`rawCfg` para habilitar. `why.mjs`/`handoff.mjs` (`requireGit:true`) não recebem — fazem sentido só com git de verdade, que `extraRepos` não promete.

- **`interface`/`type`/`enum` do TypeScript entram no índice** (branch próprio em `symbolsForCode`, antes do de `function`). Ficaram de fora até 2026-08-03 e a lacuna era grande e silenciosa: 1.592 tipos no frontend do workspace de referência (+42% no índice daquele repo) e 25 num projeto de terceiro. O sintoma não era só "não achei" — como a busca casa parcial, perguntar por `Status` devolvia **`function StatusBadge` como se fosse a resposta**, enquanto o `export type Status` real seguia invisível. O branch exige `\s+` + identificador depois da palavra-chave, que é o que impede `type: 'foo'` (propriedade de objeto, comum em JS) de virar símbolo — medido: **0 símbolos novos** nos 593 arquivos JS do backend, e 1.617/1.617 dos novos apontando para a linha real de declaração.
- ⚠️ **`X()` × `const X` é RÓTULO, e rótulo errado manda alguém ler a linha errada.** Todo binding de topo entra no índice dos dois jeitos — nada some. O que muda é a descrição, e ela mentia: a regra `^ident(` chamava de função todo `const HERE = dirname(…)`, e **9 dos 14 símbolos de `install.mjs` saíam com `()`**. Hoje são três casos: arrow/função DIRETA (o `=>` é do próprio binding), e wrapper de ordem superior — chamada de identificador **nu** com função dentro. Exigir o nome nu, sem ponto, é o que separa `handleController(async …)` (função) de `STATE_FILES.filter(f => …)` (array): os dois têm `=>`, mas chamada encadeada é quase sempre valor. **Medido por diff de conjunto nos 224 símbolos: 0 perdido, 0 inventado, 15 rótulos trocados — 14 consertados e 1 PIORADO** (`const t = makeT(detectLang())` é chamável e agora sai como `const t`). Chamada que devolve função é indecidível por regex; o balanço é 14 × 1, mas o 1 é erro, não detalhe.
- **`bareName` precisa conhecer todo rótulo novo.** O símbolo entra no índice pelo rótulo (`type Status`) mas é consultado pelo nome nu (`Status`); esquecer de somar a palavra-chave à lista de `bareName` indexa o símbolo e ainda assim não o encontra — falha que não aparece no parser, só na consulta ponta a ponta.

- 🔴 **`sourceDirs` varre a RAIZ, e adivinhar pasta de código foi o pior bug que a ferramenta teve.** Antes ela devolvia só as pastas de convenção existentes (`src`, `lib`, `tests`, `scripts`…), então bastar UMA existir apagava todo o resto — **em silêncio**. Medido: prometheus indexava **0 de 974** arquivos (100% invisível, porque tem `scripts/` e o código mora em `tsdb/`, `discovery/`, `storage/`), django 2.026 de 2.970 (32% invisível), e até os repos do workspace de referência escondiam 2 e 4 arquivos. Quem filtra lixo é `IGNORED` no `walk`, não palpite de nome. **Custo medido do conserto: zero** — 1.752 ms antes e 1.752 ms depois no mesmo workspace, porque listar diretório é 34 ms do total e o gasto real é ler bytes. `cfg.sourceDirs` continua valendo para quem QUER restringir.
- **A lista de arquivos é deduplicada antes de indexar.** `sourceDirs` devolve a raiz e `rootFiles` também devolvia os arquivos soltos dela: em repo com código na raiz (padrão em Go) cada símbolo saía DUPLICADO — cobra varria 61 para 36 reais (41%), gin 29%. Não era só feio: repetição consumia o teto de 40 acertos e inflava `fileCount`, que é quem escolhe o tier de cache. A dedupe também cobre `sourceDirs: ["src", "src/api"]` na config, que se sobrepõem.

- **Python (`symbolsForPython`): a armadilha é a docstring.** `"""…"""` atravessa linhas e em Python o exemplo de código dentro dela é o estilo dominante de documentação — sem tratá-la, `def index():` de exemplo vira definição com arquivo e linha exatos. Prefixo (`f"""`, `r'''`) precisa abrir docstring igual, senão o parser não vê o fechamento e engole o resto do arquivo. Medido em flask+requests+django (3.047 arquivos, 45.985 símbolos): **0 linha errada, 0 perdido, 92 fantasmas evitados**.
- **Go (`symbolsForGo`): três coisas que só aparecem em código real.** (1) `type (`/`const (`/`var (` agrupam declarações, e sem rastrear ANINHAMENTO os campos de um literal dentro do grupo viram declaração — `prometheus.GaugeOpts{ Name: …, Help: … }` gerava `var Name`/`var Help`, **613 símbolos falsos** no corpus. (2) O receptor pode ser genérico (`func (b Bucket[BC]) String()`); sem o `[…]` opcional, todo método de tipo genérico some. (3) `a, b = f()` declara DOIS nomes na mesma linha — indexar só o primeiro deixava o segundo inencontrável. Raw string com crase e bloco `/* */` saem antes da busca, mesma razão do Pascal. Medido em cobra+gin+prometheus (861 arquivos, 21.170 símbolos): **0 linha errada, 0 perdido**.
- ⚠️ **Ao adicionar linguagem, são QUATRO passos, não três.** Parser + `parserForExt`; **`EXTENSOES_CODIGO` em `lib/roots.mjs`** (desde 2026-08-04 é a fonte única: `CODE_RE` é derivado dela e `symbols.mjs` só importa — no lugar da definição antiga sobrou um comentário apontando para lá); `bareName`; e **trocar a extensão de exemplo nos dois testes que provam "linguagem não suportada"** (`parserForExt: despacha certo…` e o E2E `distingue pasta errada de linguagem`). O quarto já quebrou o CI duas vezes: o exemplo era `.rs`, virou `.py`, e cada um falhou sozinho quando a linguagem entrou. Hoje é `.rb`.

- **Chave de configuração entra no índice como `key X`, e a regra é ESTREITA de propósito.** Só literal de objeto aberto no topo do arquivo (`const X = {` sozinho na linha, `module.exports = {`, `export default {`) e só os filhos DIRETOS. Existe porque `sessionTimeoutMinutes`, `max_restarts` e `enableFallback` não eram acháveis de jeito nenhum — o índice só via definição de topo e método de classe. Medido no workspace de referência (1.543 arquivos JS/TS): **1.329 chaves, 832 nomes distintos, média de 1,6 ocorrência por nome**; a regra larga (qualquer `x:` em qualquer nível) daria **75.454**, 57× mais, e afogaria a busca exatamente como nome de componente `.dfm` afogaria — que é o motivo de `.dfm` estar fora do índice. Verificado por diff de conjunto: **0 símbolo real removido, 0 adição que não fosse chave**, +1.329 (índice +9,7%, parse dentro do ruído).
- **Caso de teste (`test X`) entra no índice, e a regra é a COLUNA 0.** `test`/`it`/`describe` no topo do arquivo, com string literal como primeiro argumento; `test.skip` e afins também. Aninhado **não** entra — subteste indexado devolveria o mesmo ruído que o índice evita em `.dfm`. `bareName` devolve a DESCRIÇÃO inteira, sem as limpezas de identificador: elas cortariam `montar.` de "montar.prompt preserva o bloco" e comeriam o `()` de uma função citada no fim.
- **A causa de indexar teste é a ABSORÇÃO DE INTERVALO, não navegabilidade.** `comIntervalos` fecha um símbolo na linha anterior ao próximo de mesma profundidade, e chamada `test(…)` não era símbolo nenhum: `tests/hooks-e2e.test.mjs` tinha **4 símbolos em 847 linhas**, com um helper de topo engolindo 401 — e o handoff anunciava esse helper como tocado quando o que mudou foi um teste no meio dele. Indexar os testes encolhe os intervalos até a verdade **sem tocar em `comIntervalos`**, que fecharia span por contagem de chaves e arriscaria ler a MENOS. Medido por diff de conjunto: **225 → 225 símbolos não-teste, 0 perdido, 0 inventado, +111 testes**.
- **Chave e caso de teste são resposta de SEGUNDA CLASSE: `reportOne` os ranqueia abaixo de símbolo real** (`hits.sort` por `kind.startsWith('key ')`, estável desde ES2019). Das 832 chaves, **31 colidem** com um nome já indexado; nessas a definição precisa vir primeiro, senão a chave empurraria a resposta certa para baixo do teto de 40 acertos. Mesma doutrina do "arquivo NUNCA é apresentado como definição".
- ⚠️ **O rastreio de template literal do modo-chave vale SÓ dentro do objeto.** Ele conta crases e alterna o estado no número ímpar — heurística que erra a favor de PERDER chave, nunca de inventar. Aplicá-la ao arquivo inteiro engoliria símbolo real: uma regex com crase (caso real num módulo de formatação de texto do workspace de referência) tem 3 crases, e o parser passaria a ignorar todo o resto do arquivo. Medido: com o rastreio global, 10 símbolos reais desapareciam.
- ⚠️ **O modo-chave NÃO retorna cedo quando a linha não é chave.** Método abreviado dentro do objeto (`  aoTocar() {`) precisa continuar caindo nas regras de baixo — engolir a linha seria regressão silenciosa.

- **Rust (`symbolsForRust`) tem três armadilhas próprias.** (1) Visibilidade é prefixo variável (`pub`, `pub(crate)`, `pub(super)`) — tudo opcional, então é um grupo opcional em toda regex. (2) `impl` existe em duas formas (`impl Foo` e `impl Trait for Foo`) e nas duas o que se procura é o **TIPO**, não o trait — quem resolve isso é uma regra dedicada no topo de `bareName`, antes da lista de prefixos. (3) **A ordem `fn` antes de `impl` é obrigatória**: sem ela, `fn f() -> impl Iterator` viraria um bloco `impl`. Medido em 29 arquivos reais: 1.178 símbolos, **0 apontando para linha errada**, e o conjunto de `fn` bate exatamente com o do grep nas duas direções (nenhum perdido, nenhum inventado).
- ⚠️ **A distinção `fn` (definição) × `Fn`/`FnMut` (trait em cláusula `where`) é só a CAIXA** — por isso o parser de Rust não usa flag `i` em lugar nenhum, ao contrário do de Pascal, onde a flag `i` é obrigatória. Trocar isso por descuido faz `where F: Fn(i32)` virar símbolo. **Medido em rayon** (190 arquivos, 4.600 símbolos), escolhido justamente por ter 358 ocorrências de `Fn(` em cláusula `where` e 30 de `-> impl`: **0 trait virou símbolo, 0 `-> impl` virou bloco impl, 0 linha errada**. As duas defesas eram raciocinadas até 2026-08-04; agora são medidas.

- **Pascal tem duas particularidades que o parser trata explicitamente:** a linguagem é **case-insensitive** (todas as regex usam flag `i` — `PROCEDURE` maiúsculo é comum em código legado), e **todo método aparece duas vezes** (declarado no `interface`, definido no `implementation`). A definição qualificada vira `procedure TClasse.Metodo`; a declaração vira `procedure Metodo` com `depth 1`, para o outline mostrar a estrutura da classe sem confundir as duas.
- **`semComentariosPascal` roda ANTES das regex e é a única parte do parser com estado entre linhas.** Pascal tem `{ }` e `(* *)` além de `//`, e ignorá-los não causava símbolo faltando — causava símbolo **inventado com cara de real**: prosa de doc virava `function is`/`unit for`, e bloco de API comentado virava definição. Medido em 1.164 arquivos de dois dialetos (HeidiSQL/Delphi-VCL + Double Commander/FPC-Lazarus): **168 fantasmas em 72.179 símbolos, e 84 NOMES só existiam dentro de comentário** — consultar qualquer um devolvia 100% lixo, e os caros estavam entre eles (`ContentGetValueW` respondia `wdxplugin.pas:87`, dentro de um `(* *)` que documenta a API de plugin). Duas guardas, ambas obrigatórias e confirmadas no corpus: **`{$IFDEF}` é diretiva, não comentário** (o código dentro compila e precisa continuar indexado) e **`{` dentro de string não abre comentário** — sem isso `if (c^ <> '{') then Break;` (linha real de `Img32.SVG.Core.pas`) engoliria o resto do arquivo, trocando falso positivo por perda de símbolo real, que é o pior dos dois erros. `{%H-}` do FPC é diretiva mas PODE ser apagada: some da linha e revela o símbolo que escondia (recuperou 3 `property`/`constructor` que o parser antigo perdia em silêncio).
- **O recuo que define o `depth` sai da linha ORIGINAL, não da linha sem comentário** — comentário virou espaço, e `{ nota } procedure Foo;` na coluna 0 passaria a parecer indentado, virando membro de classe.
- ⚠️ **Verificar o parser de Pascal exige oráculo que trate string.** A primeira medição usou um detector de comentário paralelo SEM tratamento de string e reportou 959 fantasmas — inflado, porque o oráculo tinha exatamente o bug que estava medindo. O número real (168) só apareceu ao diffar o conjunto de símbolos antes×depois. **Diff de conjunto é o oráculo confiável aqui; contador paralelo não é.**
- **`bareName` indexa método Pascal pelo nome final** (`procedure TPedido.Confirmar` → busca por `Confirmar`), porque é assim que se procura. O rótulo completo com a classe continua aparecendo na saída, então o contexto não se perde.
- **Busca qualificada (`Classe.Metodo`) espelha o mesmo corte que `bareName` já fazia na indexação — `QUALIFICADOR_RE`, constante única usada nos dois lados.** Caso real (2026-08-05, mesma investigação do `extraRepos`): com o índice já enxergando `TExporter.RegistroABC` via `extraRepos`, a busca pela query QUALIFICADA (`symbols.mjs TExporter.RegistroABC`) ainda voltava vazio — só `RegistroABC` nu achava. Causa: `bareName` já indexava sem o prefixo de classe, mas `reportOne` testava a regex contra a query ORIGINAL, com prefixo — `TExporter` nunca aparece em nome nenhum do índice, então o `RegExp.test` falhava sempre, mesmo com a definição presente. `query` (com qualificador) continua indo para as mensagens ao usuário; só `queryNua` (com o mesmo corte de `bareName`) vai para o regex e para a comparação de exact match. Não é heurística nova — é a MESMA regra já provada na indexação, agora espelhada; zero mudança para busca sem qualificador.
- **`.dfm`/`.fmx` estão fora do `CODE_RE`** do índice cross-file, de propósito: nome de componente (`Button1`, `Panel2`) repete em todo formulário e afogaria a busca. São suportados só no `outline`, para navegar um formulário grande.

- **O cache MEDE a granularidade do relógio do FS antes de confiar nele** (`mtimeGranularityIsFine`): grava uma sonda na mesma partição do projeto (temp do SO pode ser outro volume) e checa se o mtime tem fração de segundo. Granularidade grosseira ⇒ recusa o cache e diz isso na saída (`cacheRecusadoPeloFs`). Falha ao sondar também recusa — se não dá para escrever a sonda, não daria para escrever o cache.
- **Nenhum dos dois lê arquivo de código com `readFileSync(...,'utf8')` — os dois usam `lerTexto` (`lib/roots.mjs`).** UTF-8 estrito com fallback para latin1, e BOM removido. As duas falhas que isso mata eram silenciosas e atacavam justamente quem o índice deveria servir: BOM (padrão dos editores da Microsoft) escondia o PRIMEIRO símbolo de cada arquivo, porque o `﻿` cola na linha 1 e `^export function` deixa de casar; e arquivo cp1252 (Delphi legado, a linguagem com mais código antigo) virava `function Endere<FFFD>o`, então buscar `Endereço` não achava nada. **`readFileSync` cru em parser novo é regressão.**
- **A lista de extensões nas MENSAGENS vem de `EXTENSOES_LIDAS`, nunca escrita à mão.** A cópia manual já mentiu: Python e Go entraram no índice e o diagnóstico seguiu dizendo "Lê: js/…/rs", afirmando não ler a linguagem que acabara de passar a ler e mandando o usuário embora sem motivo. Numa ferramenta cuja tese é "falha visível", errar na própria mensagem de falha é o pior lugar possível.
- **Toda mensagem passa por `t()`** (`lib/i18n.mjs`), padrão inglês. String literal nova em português no meio do código é regressão.
- **Todo campo que carrega texto de origem não confiável (nome de arquivo, nome de símbolo, rótulo de escopo, query do usuário) passa por `sanitizeModelText`** (`lib/roots.mjs`) antes de compor a saída em `formatarAcertos`, `escopoLabel` e `reportOne` — remove controle/ANSI e trunca. Mesma função usada em `coupling.mjs` (ver `change-coupling.md`); escrever um `${valor}` cru de volta na saída é regressão.

- **Cada símbolo carrega onde TERMINA** (`comIntervalos`), não só onde começa: o fim é a linha antes do próximo símbolo de `depth` igual ou menor — por isso uma classe abrange seus métodos em vez de parar no primeiro. Motivo medido: 5.985 símbolos reais deste workspace têm **mediana de 16 linhas** (p75 = 38), mas quem só recebe a linha inicial chuta 40 — ~2,5× de desperdício na leitura seguinte. O erro possível é incluir comentário entre símbolos (ler a MAIS); nunca ler a menos.
- **O par declaração+implementação do Pascal é agrupado numa linha** (`formatarAcertos`): sem isso toda busca em Delphi devolvia dois blocos. Só agrupa o par exato — 3+ ocorrências são ambíguas e seguem listadas uma a uma, sem inventar relação.

## Gotchas (queimam em silêncio)
- ⚠️ **A regra de "método indentado" só liga em arquivo que tem `class`** (`hasClass` em `symbolsForCode`). Sem essa guarda, em componente React ela capturava CHAMADAS indentadas (`setForm(...)`) como se fossem definições. Falso positivo em outline é pior que símbolo faltando: manda o Read pra linha errada.
- ⚠️ **`symbolsForMarkdown` tira `\r` ANTES de casar a regex.** Em JS, `.` não casa `\r` — sem isso, arquivo CRLF devolvia "nenhum símbolo" num `.md` cheio de headings. Bug já corrigido; não reintroduzir ao mexer no parser.
- ⚠️ **`outline.mjs` só roda `main()` se invocado direto** (guarda `isMain`, de `lib/roots.mjs`). Sem ela, `symbols.mjs` importar o parser dispararia `main()` + `process.exit(0)` como efeito colateral. `isMain` compara o caminho RESOLVIDO, não o basename: existem duas cópias de cada script (a fonte e a instalada em `.claude/scripts/`), e comparar só o nome confundiria as duas. **Este item citava um nome de guarda que não existe mais — foi o achado real que a auditoria dos mapas pegou no dia em que passou a rodar sobre eles.**
- ⚠️ O índice só vê **definições de topo e métodos de classe**. Variável local dentro de função, propriedade de objeto exportado e chave de config são invisíveis — é limitação de desenho (regex, não AST), não bug. A mensagem de falha já diz isso ao usuário.
- Ao filtrar por regex, o padrão vem do usuário: `symbols.mjs "^index$"` casa exato, `symbols.mjs index` casa parcial (case-insensitive). Consulta ampla em repo grande pode estourar o cap de 40 (ou 200 com `--all`).

- ⚠️ **`findRepos` é chamado com `requireGit:false` aqui.** Symbols precisa só dos ARQUIVOS, não de histórico — sem isso, projeto sem versionamento (ou svn/hg) recebia "nenhum arquivo de código encontrado" e a ferramenta ficava morta. `why.mjs` continua em `requireGit:true` (não há substituto sem git para "por que esta linha é assim"). Desde 2026-08-05 `coupling.mjs` também chama `requireGit:false` — não porque passou a dispensar histórico, mas porque ganhou um substituto mais fraco (sessão registrada em vez de commit) para quando não há `.git`; ver `change-coupling.md`.
- ⚠️ **`(?i)`/`(?-i)` no filtro de `outline.mjs` é descartado antes de montar o `RegExp`** (`stripInlineRegexFlags`). É sintaxe de modificador inline de Python/PCRE — inválida em JS — e quem escreve nesse hábito (ou um LLM treinado nesses dialetos) tomava "filtro inválido" mesmo com o resto do padrão correto. Como o filtro já é case-insensitive por padrão, descartar o prefixo é sempre seguro quando ele aparece.

## Não cobre (e por quê)
- `coupling.mjs` (histórico do git) e `audit-docs.mjs` (auditoria de doc) — concerns independentes, sem relação de import com estes dois.
- `context-maps.mjs` e o sistema de hooks — mapa próprio em `context-maps-hook.md`.
- `lib/roots.mjs` (descoberta de raiz/repos) — coberto pelo mapa `context-maps-hook`, usado pelos dois.
- Tier por `git diff` para repos gigantes (>100k arquivos) — avaliado e **descartado**: só cobre arquivo rastreado, exigiria combinar com `git status --others`, e os ~520 ms de `stat` em 20k já resolvem. Menos peças móveis vence.

## Persistência de métricas (1.23.0)

`lib/telemetry.mjs recordMetric` usa transação exclusiva compartilhada de state-store para não perder
incrementos concorrentes no anel de 2.000 eventos. A alteração não amplia conteúdo coletado por
symbols/outline nem transforma resultado oferecido em prova de uso pelo agente.
